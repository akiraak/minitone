# MID の表記を VOICE にするかの検討

## 目的・背景

2026-11-20 にユーザーが「Midの表記はVoiceにしたら分かりやすくなるか分かりにくくなるか考える」と指示した。

MID のツマミは、2 kHz を中心にした山の形のフィルタ（Q 0.7、およそ 1〜4 kHz、±20 dB）。この周波数は、声の聞き取りに効く帯域として選んだ（[済んだプラン](archive/three-band-tone.md)）。

この文書は検討だけ。コードは変えていない。

## 対応方針

分かりやすくなる点と、分かりにくくなる点を並べ、おすすめを出す。決めるのはユーザー。

## VOICE にすると分かりやすくなる点

1. **何のためのツマミかが、名前で分かる。** 音に詳しくない人は「MID（中音）」を回すと何が変わるかを知らない。「VOICE」なら、声が聞き取りにくいときに回すものだと分かる。
2. **このツマミを選んだ理由と合っている。** 2 kHz にしたのは、動画や会議の声を聞き取りやすくするため。上げると、実際に声が前に出る。

## VOICE にすると分かりにくくなる点

1. **声だけが変わるように読める。** 実際には 1〜4 kHz の音が全部動く（ギター、スネア、効果音も）。テレビやサウンドバーの「クリアボイス」のような、声だけを強める機能を期待させる。
2. **下げたときの意味が合わない。** 「VOICE を下げる」は、声が小さくなる、歌が消えると読める。実際には、声の基音（100〜300 Hz）は残り、こもって遠くなるだけ。音楽で中音を下げて低音と高音を目立たせる使い方（「VOICE −6 dB」）は、名前から思いつかない。
3. **並びの種類がそろわない。** BASS と TREBLE は音の高さの名前、VOICE は音の中身の名前。BASS、MID、TREBLE は、アンプやミキサーで広く知られた 3 つの並びで、画面のデザイン（アンプの前面パネル）とも合っている。
4. **曲線の表示と合わない。** 横が周波数のグラフでは、点の名前は BASS、MID、TREBLE（低い順）が自然。まんなかの点だけ VOICE になる。
5. **直すものがある。** 画面の名前（ツマミ、バー、グラフ、読み上げ用の名前）、README の説明と絵 3 枚、CLAUDE.md。設定ファイルと APO は変えない。

## ほかの名前

- PRESENCE: ギターのアンプで、この帯域に使う名前。音に詳しくない人には MID より分かりにくい。
- VOCAL、CLARITY: VOICE と同じ問題がある（声だけ、または「はっきりさせる機能」に読める）。

## おすすめ

**MID のままにする。** VOICE は「声を聞き取りやすくする」という 1 つの使い方では分かりやすいが、声だけが変わると読めること、下げる方向の意味が合わないことで、全体では誤解が増える。

声に効くことを伝えたいなら、名前は変えずに補う。

- MID のツマミ、バー、点にマウスを載せたときの説明（"Mid — around 2 kHz, where voices are" など）を出す。
- README の使い方に「声が聞き取りにくいときは MID を上げる」と書く。

MiniTone の主な使い道を「声を聞き取りやすくすること」に絞り、音に詳しくない人だけに向けるなら、VOICE にする選択もありうる。

## 「MID (VOICE)」と書く場合の検証（2026-11-20）

ユーザーが「MID(VOICE)の表記にした場合で検証して」と指示。画面のファイルの写しで名前だけを変え、ヘッドレスの Edge に 3 つの表示を描かせて見た。アプリのコードは変えていない。絵はコミットしない（ユーザーの「ダウンロード」フォルダの `minitone-mid-voice.png`）。

### 見た目

| 案 | 中身 | ツマミの表示 | バーの表示 | 曲線の表示 |
|---|---|---|---|---|
| V1 | 名前を "MID (VOICE)" にするだけ | 入る。名前がほかの倍の長さ | **2 行に折れて崩れる**（名前の列が 66 px） | 入る。TREBLE との間は約 45 px |
| V2 | V1 + バーの名前の列を 66 → 106 px | V1 と同じ | 入る。バーが 40 px 短くなる（LED 1 粒が約 1 px 細くなる） | V1 と同じ |
| V3 | "MID" はそのまま、"(VOICE)" を小さく暗い字で添える | 入る。MID が主、VOICE が添え書きに見える | 入る。名前の列は 90 px、バーは 24 px 短くなる | 入る |

- ツマミの列の幅（116 px）には、どの案も入る。V1、V2 は、4 つの名前のうち 1 つだけ長く、並びのそろいが崩れる。
- V3 がいちばん収まりがよい。"(VOICE)" は 8.5 px なので、小さい画面では読みにくい。

### 意味

- **MID が主なので、VOICE だけにしたときの誤解が減る。** 並び（BASS、MID、TREBLE）はそのまま。かっこの中は「たとえば声」という補いに読める。下げる方向（中音を引く）も MID として通じる。
- **「声だけが変わる」とは読みにくくなるが、ゼロではない。** "MID (VOICE)" を「MID すなわち VOICE」と読む人はいる。V3 のように小さく添えるほうが、補いだと伝わる。
- **常に見えるので、マウスを載せたときの説明より気づきやすい。** 説明は、載せないと出ない。
- **パネルの文字が増える。** いまは名前 5 つと値だけの、アンプの前面パネルのような画面。かっこ書きは、パネルの表記としては珍しい。

### おすすめ（検証のあと）

**入れるなら V3。** 声に効くことが常に見え、MID の並びと意味は保てる。V1 はバーの表示が崩れるので、そのままでは使えない。V2 は使えるが、名前の長さがそろわない。

「MID のまま、説明はマウスを載せたときと README」と V3 の差は、画面のすっきりさと、気づきやすさのどちらを取るか。音に詳しくない人に使ってもらうことを重く見るなら V3、パネルの見た目を重く見るなら MID のまま。

## 結果（2026-11-20）

ユーザーが「V3 で実装して」と決定。作った。

- `app/ui/index.html`: ツマミとバーの名前を `MID<small> (VOICE)</small>` にした。読み上げ用の名前は "Mid (voice)"。
- `app/ui/main.js`: 曲線の表示の MID の名前に、小さい字の "(VOICE)" を添える。
- `app/ui/style.css`: 添え書きの字（8.5 px、暗い色）。バーの名前の列を 66 → 90 px（バーは 24 px 短くなる）。
- 設定ファイル、APO、Rust 側は変えていない。内部の名前は `mid` のまま。
- README に、MID が声の帯域であることを 1 行足し、絵 3 枚を作り直した。
