# 「APO を 1 つだけ書く古い形」のデバイスにも取り付ける

## 目的・背景

- 2026-11-20、titan に v0.1.0 のインストーラを入れたところ、画面の「Enable」で "Could not enable MiniTone on this device." と出た。
- 原因: titan の既定の出力デバイス（NVIDIA の HDMI の音、Odyssey G95NC）と Bluetooth のヘッドホン（WH-CH720N）は、
  FxProperties の MFX の段に Windows 標準の APO（`{13AB3EBD-137E-4903-9D89-60BE8277FD17}`）が
  「1 つだけ書く古い形」（`{d04e05a6-…},6`）で入っている。SFX も古い形（`,5`）。並べる形（`,13`〜`,15`）は無い。
- `install-apo.ps1` は、この形で段が埋まっているデバイスを「対応していない」として飛ばし、終了コード 0 で終わっていた。
  画面はスクリプトが成功したのに付いていないので、理由の無いエラーを出した。
- sx360 と titan の Realtek は並べる形なので付いた。

## 対応方針

### 1 回目（効かなかった）

- 古い形の値はそのままにして、並べる形の値（`,13`、`,14`）を作った。登録はできたが、WH-CH720N で鳴らした音に APO が入らなかった
  （設定を変えても APO が読み直さない＝音の経路に APO の実体が無い。2026-11-20、titan）。
  Windows は、古い形の値があるデバイスでは並べる形の値を読まないと考えられる。

### 2 回目（2026-11-20、ユーザーが選んだ）

- 古い形だけのデバイスで、取り付ける段（MFX の `,6`）がドライバの APO で埋まっていれば、その値をこの APO に置き換える。
  - 元の APO は `install-state.json` の `ReplacedValues`（`デバイス|値の名前|元の CLSID`）に記録し、`uninstall-apo.ps1` が戻す。
  - 置き換えたあいだ、そのデバイスでは元の APO（Windows の「オーディオの強化」の MFX の部分）は働かない。
  - 比べた案: この APO の中から元の APO を呼ぶ。「オーディオの強化」を残せるが、APO の中の処理が大きくなり、落ちると全体の音が止まる。採らない。
- 1 回目で作った並べる形の値（`CreatedValues` にある `,13`〜`,15`）は、登録のときに消す。いまつながっていないデバイスでも消す。
- 段が空いている古い形のデバイスは、いままでどおりこの APO を書く。

## 影響範囲

- `apo/scripts/install-apo.ps1`、`apo/scripts/uninstall-apo.ps1`。
- 画面のアプリとインストーラは、同梱するスクリプトが変わるだけ。

## テスト方針

- titan で `install-apo.ps1 -AllDevices -DryRun` を実行し、Odyssey G95NC と WH-CH720N に行う変更を確かめる（確認なしで実行してよい）。
- `uninstall-apo.ps1 -DryRun` は、登録したあとでないと意味が無いので、ユーザーが入れたあとに確かめる。
- インストーラをビルドし、ユーザーが titan で上書きインストールする。
  - HDMI（Odyssey G95NC）で音が出ること、ツマミが効くこと。
  - APO のログに、HDMI のデバイスの読み込みが出ること。
- 解除して、作った値が消え、元の値が残ることを確かめる（ユーザーが実行）。

## わかっていないこと

- 2 回目の方法で、WH-CH720N と HDMI に効くか（ユーザーが確かめる）。
