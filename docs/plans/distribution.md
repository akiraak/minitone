# 配布の準備

## 目的・背景

MiniTone を、作者以外の人が入れて使える形にする。いまは、README が日本語で、インストーラは自分でビルドする前提、動かしたのは作者の PC 1 台だけ。

2026-11-20 にユーザーが「README.md を英語にする。その他、配布に必要なことを洗い出す」と指示した。

## 対応方針

- Step 1: README.md を英語にする（済み）。日本語版は残さない（Git の履歴にある）。
  - 電源の説明が古かった（「スイッチを上に」）ので、丸い押しボタンの説明に直した。
  - 画面の文字が日本語のままなので、README にそう書き、ボタンの名前は日本語のまま引用した。画面を英語にしたら README も直す。
- Step 2: 配布に必要なことを洗い出す（この文書の下の一覧。済み）。
- Step 3 以降: 一覧の項目を、ユーザーが選んだ順に進める。項目は `TODO.md` の子タスクにした。

## 洗い出した項目

### A. 無いと配れないもの

1. **ビルド済みのインストーラを配る。** GitHub の Releases に `MiniTone-setup.exe` を置く。バージョンのタグ（`v0.1.0`）、変更点、SHA-256 を付ける。README の「自分でビルドする」を「Releases から落とす」に直す。
2. **画面の文字を英語にする。** 日本語で固定になっている場所:
   - `app/ui/main.js` と `index.html`（知らせの文、「効くようにする」、`lang="ja"`、`aria-label`）
   - `app/src-tauri/src/main.rs`（トレイのメニュー「開く」「イコライザーの入り切り」「終了」、エラーの文）
   - `app/src-tauri/src/devices.rs`（取り付けのエラーの文）
   - `apo/scripts/*.ps1` の表示とエラー（インストーラのログと、失敗したときに使う人が読む）
   - 決めること: 英語だけにするか、Windows の表示言語で日本語と英語を切り替えるか。
3. **作者の PC 以外で確かめる。** まっさらな Windows 11（別の PC か仮想マシン）で、インストール、音、アンインストールで元に戻ること。
   - 画面のアプリ（Rust）は C のランタイムを静的にリンクしていない（`crt-static` の指定が無い）。`VCRUNTIME140.dll` が無い PC で起動できるかを確かめる。だめなら `crt-static` を付ける。APO の DLL は `/MT` なので問題ない。
   - 音のドライバの違い（Realtek、USB、HDMI、Bluetooth）。
   - Equalizer APO など、ほかの APO のソフトが入っている PC での共存と、アンインストールのあとの状態。
   - 既にある `TODO.md` の「残りの確認をする」（DRM 付きの再生、ほかのデバイス、タスクトレイ）もここに含まれる。

### B. 配る前に決めること

4. **インストーラの署名。** 署名が無いと、SmartScreen の警告が出て、ウイルス対策のソフトが誤って止めることがある。証明書を買うか、署名なしのまま README で知らせるかを決める（APO の DLL を署名しない方針は変えない）。
5. **対応する環境をはっきりさせる。** いまは x64 の Windows 11 だけ。Windows 10 と Arm64 を「対応しない」と書くだけにするか、インストーラで止めるか。
6. **新しい版の入れ方。** 自動の更新は無い。上書きインストールで更新する、と README に書く。バージョンの番号は `tauri.conf.json` と `Cargo.toml` の 2 か所にあるので、上げる手順を決める。

### C. あるとよいもの

7. **同梱しているものの権利の表記。** Tauri と Rust のクレート（MIT / Apache-2.0）の表記を集めて、インストーラに入れる（`cargo-about` など）。
8. **GitHub のリポジトリの見た目。** 説明とトピックが空。README に画面の絵を入れる。
9. **不具合の報告のしかた。** README に、Issue に書いてほしいこと（Windows の版、出力デバイス、APO のログ）を書く。音が出なくなったときの戻し方を「困ったとき」としてまとめる。
10. **Windows の起動で自動的に常駐させるか。** いまは自動では起動しない（APO は設定ファイルを読むので、アプリが動いていなくても音には効く）。
11. **自動のビルド（GitHub Actions）。** タグを付けたら、テストを走らせてインストーラを Releases に置く。
12. **winget への登録。** Releases が安定してから。

## 影響範囲

- Step 1 と 2 は文書だけ（`README.md`、`TODO.md`、この文書）。コードと音の経路は変えない。
- A-2（英語にする）は画面のアプリとスクリプト、A-3 の `crt-static` はビルドの設定に手が入る。

## テスト方針

- Step 1: README の中のリンク（見出しへのリンク）が合っていること、コマンドとパスが日本語版と同じことを読み比べる。
- それ以降の項目は、着手するときに項目ごとに決める。
