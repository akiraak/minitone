# イコライザーの処理と、動かしながら設定を反映する仕組み

## 目的・背景

素通しの APO が sx360 で動いた（[自前の APO を作る](custom-apo.md) の Phase 3）。
次に、APO の中でイコライザーの処理を行い、画面から値を変えたらすぐ音に反映されるようにする。
画面（Tauri 2）はこのプランの外。ここでは、画面が書くことになる設定ファイルと、APO 側の処理までを作る。

## 対応方針

### 設定の渡し方

- 画面は設定ファイル `C:\ProgramData\akiraak-minitone\config\settings.txt` を書く。APO はそれを読む
  - APO は LocalService の権限で動き、ユーザーのフォルダは読めない。ProgramData は読める
  - `config` のフォルダだけ、一般のユーザーが書けるようにする（登録のスクリプトが権限を付ける）。画面を管理者で動かさずに済む
- 形式は 1 行に 1 項目のテキスト。APO の中に重いパーサを持ち込まない

```
enabled=1
preamp=-3.0
band=1000,4.5,1.41
```

- `enabled`: 0 ならオリジナルの音（素通し）。`preamp`: 全体の音量（dB）。`band`: 周波数（Hz）、増減（dB）、Q。バンドは最大 32 個
- ファイルが無い、読めない、中身が壊れているときは素通しにする

### 反映のしかた

- DLL の中に見張りのスレッドを 1 つ持ち、設定ファイルの更新時刻を 250 ms ごとに見る。変わっていたら読み直し、版の番号を進める
- 音の処理（`APOProcess`、リアルタイムのスレッド）は、版の番号が変わっていたら新しい設定を取り込み、フィルタの係数を計算し直す
  - 取り込みは「待たないロック」（取れなければ次の回に回す）で行う。リアルタイムのスレッドを待たせない
  - 係数の計算はメモリの確保をしない
- ファイルの読み取りとパースは、見張りのスレッドだけが行う

### フィルタ

- バンドごとにピーキングの双二次フィルタ（RBJ の式）。チャンネルごとに状態を持つ
- 対応するチャンネルは 8 まで。それより多い形式は素通しにする

### Step

1. フィルタの計算と設定ファイルの読み取り（Windows の音のエンジンに依存しない形で書き、単体テストを付ける）
2. APO に組み込む。見張りのスレッド、設定の取り込み
3. sx360 で、音を鳴らしながら設定ファイルを書き換えて確かめる

## 影響範囲

- `apo/src/`（処理の追加）、`apo/test/`、`apo/scripts/`（設定のフォルダの作成と権限）
- 動作確認用の音量（レジストリの `TestGainPercent`）は、`preamp` で代わりになるので無くす
- sx360: DLL の入れ替え（ユーザーが登録のスクリプトを実行する）

## テスト方針

- フィルタ: 中心の周波数で指定の dB になること、0 dB のバンドだけなら音が変わらないこと、高い音量の入力でも発散しないこと
- 設定の読み取り: 正しいファイル、壊れた行、範囲外の値
- APO: 音のエンジン無しのテスト（`host_test`）で、設定ファイルを差し替えて、素通しと音量の変化を確かめる
- sx360: 耳で確かめる。ログでエラーが出ていないことを確かめる

## 結果（2026-11-19）

- Step 1〜3 を終えた。単体テストと、音のエンジン無しのテストは全部通る
- sx360（Bluetooth のヘッドホン）で、再生中に設定ファイルを書き換えて確かめた
  - 4 kHz と 10 kHz を −18 dB にすると、音がこもって聞こえた。音のサービスの再起動なしで反映された
  - 80 Hz を +8 dB、全体を −8 dB にした設定は、違いが分からなかった。骨伝導のヘッドホンは低音が出にくく、全体の音量も下げたため。確認には向かない設定だった
  - `enabled=0` に書き換えると、APO は素通しになる（ログで確認）
- 残り: 画面（別のプラン）。設定を切り替えた瞬間の音のつながり（入り切りのときに小さな雑音が出ないか）は、耳ではまだ確かめていない
