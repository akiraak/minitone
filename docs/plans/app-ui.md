# 画面（Tauri 2）を作る

## 目的・背景

APO は設定ファイルに従ってイコライザーをかけ、変更を再起動なしで反映する（[プラン](archive/eq-processing.md)）。
ここでは、その設定ファイルを書く画面を作る。画面は Windows の音の経路には触らない。

## 対応方針

### 機能（2026-11-19 にユーザーが決定）

- 3 つのツマミ: **Treble、Bass、Volume**
  - Treble: 高音側のシェルビング（5 kHz から上）、±20 dB
  - Bass: 低音側のシェルビング（150 Hz から下）、±20 dB
  - Volume: 0〜150%。100% が元の音量
  - 幅は、いったんアンプ（BT20A MAX のレビューにある ±10 dB）に合わせたあと、ユーザーの希望で ±20 dB に広げた（2026-11-19）。大きく上げると音が割れやすい。別の機種（TB10D）の実測では Treble が +7 dB という記述もあり、機種で違う
  - 効く周波数（150 Hz、5 kHz）は、メーカーの仕様や実測の数字が見つからなかったので、トーンコントロールとして一般的な値を置いている。聞いて決める
  - ツマミのまんなかは音を変えない位置。まんなか付近で止まりやすくしてある（同じメーカーの BT20A Pro のツマミも、まんなかで止まる）
- 入り切りのスイッチ。切るとオリジナルの音（要件）
- 設定は全デバイス共通
- タスクトレイに常駐する。ウィンドウを閉じてもトレイに残る。トレイのメニューから開く・入り切り・終了
- 最初に作った 10 バンドのスライダーの画面は、この決定でやめる

### デザイン

- ハードウェアのアンプの前面パネル（回すツマミ）の雰囲気にする。ユーザーが挙げた実在のアンプは参考にとどめ、ロゴ、名前、製品そのものの見た目は写さない
- デザイン案を 5 つ作り、ユーザーが **A（黒いアルミのパネル、オレンジの指針、Volume のツマミだけ大きい）** を選んだ（2026-11-19）
- 2026-11-20 にユーザーの指示で変更した:
  - ウィンドウを小さく、横長にする（600 x 190）
  - 左上の「EQUALIZER」の文字を消す
  - 電源は、ハードウェアのアンプにあるようなトグルスイッチ（レバーが上で ON、下で OFF）にして、TREBLE の左に置く。メーカーのロゴや名前は入れない
  - 電源のトグルスイッチは、見た目が不採用になった。5 案から「丸い押しボタン」、大きさ 5 案から「直径 52 px」をユーザーが選んだ。ON のときは周りのリングと電源のマークがオレンジに光る。位置は TREBLE の左のまま
  - VOLUME のツマミを、TREBLE、BASS と同じ大きさにする
  - 並びは左から POWER、TREBLE、BASS、VOLUME
- ツマミの操作: 上下にドラッグ、ホイール、矢印キー。Shift を押しながらドラッグすると細かく動く。ダブルクリックで元の位置（0 dB、100%）に戻る

### 作り

- `app/src-tauri/` — Rust。設定ファイルの読み書き（一時ファイルに書いてから置き換える）、トレイ
- `app/ui/` — 素の HTML / CSS / JavaScript。Node.js を使わない
- 設定ファイル（`C:\ProgramData\akiraak-minitone\config\settings.txt`）が、設定の唯一の置き場所。画面は起動時にそれを読む
- APO が入っていない（設定のフォルダが無い）ときは、画面でそれを知らせる

### Step

1. 骨組み: Windows 側でビルドでき、ウィンドウが出るところまで（済み。10 バンドの版でビルドとテストが通った）
2. デザイン案を選んでもらう
3. 選ばれたデザインで、3 つのツマミの画面と設定の読み書きを作り直す
4. タスクトレイ（コードは書いてある。画面を出して確かめる）
5. APO の DLL を入れ替える（シェルビングと音量に対応した版。ユーザーが管理者で実行）
6. sx360 で、ツマミを回して音が変わることを確かめる

## 影響範囲

- `app/` を新しく作る。APO のコードは変えない
- sx360: ビルドに使う Rust のクレートを取ってくる。Rust の更新が要るときは、ユーザーに確認する

## テスト方針

- 設定ファイルの書式（書く・読む）は Rust の単体テストで確かめる
- 画面の操作と音は、sx360 でユーザーに確かめてもらう
